未登入隱藏賣家聯絡方式

採用方案 A（模糊遮罩）+ C（點擊觸發 Modal），而 C 的 Modal 不另外做 —— 直接復用既有的 BuyerClubPopup。未登入訪客在 /store/[storeId] 看到的是模糊的聯絡方式與上鎖的 CTA；點任何一個鎖，就開買家俱樂部註冊 Modal；註冊完成後原地解鎖，不換頁、不刷新。

為什麼把 C 換成 Buyer Club Popup

原本 C 方案要做一個新的「登入 Modal」，走 /login?redirect=… 再導回物件頁。但站上已經有 BuyerClubPopup：同一個頁面、同一群未登入訪客、同一個目標（註冊），而且它的 signup() 成功後 onAuthStateChanged 會直接觸發，不需要換頁就能解鎖。再做一個登入 Modal 只會變成兩個彈窗互相打架。

所以整合後只有一個 Modal、一份註冊表單、一組事件，差別只在 source：自動彈出是 auto / fab / url_force，從聯絡方式點進來的是 contact_gate，並依此切換文案。

為什麼是「模糊」而不是整段拿掉

  • 版面高度與已登入時幾乎一致，登入前後不會跳版；行動版尤其明顯。
  • 三行模糊清楚傳達「電話、LINE、Email 都有」，比一句「請登入」更有拉力。
  • CTA 兩顆按鈕保留原位、只加上 🔒，點下去的期待落差最小 —— 使用者 本來就是想聯絡，Modal 出現在這個時機是合理的。

三個觸發點都開同一個 Modal

  • ① 模糊層 → source: "contact_gate_blur"
  • ② 撥打電話 → source: "contact_gate_cta_phone"
  • ③ 加 LINE → source: "contact_gate_cta_line"
模糊只是視覺，資料一定要在伺服器端拿掉。 page.tsx 是 server component，目前聯絡方式直接進 HTML。未登入時要把 userInfo.phone / lineId / email 換成固定佔位字串 （例如 0000-000-000）再傳進卡片，真值只在登入後由 client 端 / API 取得。只做 CSS blur 等於把賣家個資公開在原始碼裡。

和既有 Popup 的整合規則

現在的 popup 有「每天自動開一次 + 關掉後變 FAB」的行為，接上解鎖入口後要處理這幾個衝突。

情況 行為 理由
今天已自動彈過、已被關掉 點鎖照樣開，不受 buyerClubPopupSeen 限制 每日上限是給「打擾」用的；使用者主動點鎖是明確意圖
點鎖開啟 不寫入 markSuppressed() 主動開啟不該消耗當天的自動彈出額度（與 forceOpen 一致）
自動彈出正開著時點鎖 無事發生（Modal 已開） 避免重複 impression 事件與重複動畫
自動彈出 vs 解鎖入口的 impression 共用 buyer_club_popup_impression，用 source 區分 GA4 可直接比較哪個入口帶來的註冊比較多
從鎖開啟後關掉 Modal 卡片回到模糊狀態，FAB 照常顯示 入口永遠在，不會因為關過一次就再也找不到
註冊成功 Modal 關閉 → 卡片 unblur（reveal 動畫）＋ 顯示「已加入買家俱樂部」 onAuthStateChanged 一次觸發兩邊，不需要 router.refresh() 或換頁
已售出（isSold） 維持現狀：不顯示聯絡方式、也不顯示鎖 已頂讓的物件登入了也沒東西可看，不該騙人註冊
狀態放哪裡：popup 的 open 目前是元件內部 state，外面的卡片打不開它。建議加一顆 Jotai atom （atoms/BuyerClubAtom.ts：buyerClubOpenAtom + buyerClubSourceAtom）—— 專案已經用 Jotai 管篩選狀態，這是最輕的做法，也避免把 popup 整個往上提到 page 層。

實作清單

預計動到 6 個檔案，其中 2 個是新增。

app/(new)/store/[storeId]/page.tsx

未登入時不把真實聯絡方式送進 HTML。因為 Firebase auth 在 server 端讀不到，實務上是：server 一律傳佔位值，真值由 SellerContactGate 登入後再取。

_components/SellerContactGate.tsxNEW

client component。跑 onAuthStateChanged，三態渲染： 載入中 skeleton / 未登入模糊＋鎖 / 已登入真實聯絡方式。點鎖時寫入 buyerClubOpenAtom。

_components/StorePriceCard.tsx

把 .sellerContact 與 .cta 兩段換成 <SellerContactGate>， isSold 的既有分支維持不變。

_components/BuyerClubPopup.tsx

open 狀態改讀 Jotai atom（保留原本的每日自動彈出邏輯）；依 source 取文案表；contact_gate 開啟時跳過 markSuppressed()。

atoms/BuyerClubAtom.tsNEW

buyerClubOpenAtom、buyerClubSourceAtom， 讓卡片與 popup 跨元件溝通。

docs/analytics-events.md

補上 contact_gate_view / contact_gate_click 兩個事件與新的 source 值。

附錄 · 原始三方案與比較表

第一版提了三個方案：A 模糊遮罩、B 鎖定面板（聯絡列整段換成一塊說明 + 登入按鈕的虛線面板）、C 點擊觸發 Modal。最後採用 A + C，B 的「說明為什麼要登入」則被吸收進 Modal 左欄的 contact_gate 文案裡。

面向 A 模糊遮罩 B 鎖定面板 C 點擊 Modal
註冊轉換 中 — 好奇心驅動 中高 — 講清楚價值 高 — 抓住意圖那一刻
信任感 偏低（像 paywall） 高（說明保護屋主） 中（CTA 有點誘導）
實作成本 低 低 中高（復用 popup 後降為中）
版面衝擊 幾乎為零 大（多一塊面板） 幾乎為零
個資風險 高（容易只做 CSS） 低（根本不 render） 低（伺服器端遮罩）

A 的個資風險靠「伺服器端傳佔位字串」解掉；C 的實作成本靠「復用 BuyerClubPopup」解掉 —— 這兩點就是整合版存在的理由。
